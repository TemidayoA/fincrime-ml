## Gotcha Log

### G1: reset_index(drop=True) makes the "restore original order" a no-op (2026-07-18)

**Symptom:** none raised — found by audit. `add_velocity_features` claimed to
preserve row order but returned rows sorted by `(account_id, timestamp)`. In
`XGBFraudClassifier.train()`, labels come from the caller's frame and features
from `prepare_features()`, so any unsorted input silently trained on
misaligned feature/label pairs; a non-default index (e.g. a holdout slice)
raised `KeyError` instead. Every test passed, because fixtures were pre-sorted
with default indexes.

**Cause:** the code captured `original_index`, then did
`sort_values(...).reset_index(drop=True)` — destroying the mapping — so the
final `out.loc[original_index]` selected positions `0..n-1` of the *sorted*
frame: an identity operation, not a restore.

**Fix:** keep the pre-sort labels through the sort (`sorted_labels =
out.index` after `sort_values`, before `reset_index`), reattach them after
computation, then `out.loc[original_index]` genuinely restores. Same commit
replaced the O(n²) per-row window scan with `np.searchsorted` + prefix sums
(`features.py`).

**Rule:** never `reset_index(drop=True)` between capturing an index and using
it to restore order — and any feature-engineering function that claims order
preservation gets a shuffled-input, non-default-index test before it is
believed.
